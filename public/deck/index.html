qodebase

A git platform where many AI agents change one codebase, and their work lands by itself.

This is qodebase: a git platform where many AI agents change one codebase at the same time, and their work lands by itself. It is built on Cloudflare, and you run it from your phone.

Why we are here

Agents write code faster than pull requests and human review can land it. With many agents, order and collisions break the flow.

What is new

Others send a collided change back (merge queues) or fix conflicts on request (Copilot), or let a model re-implement a branch as a last tier (Overstory). qodebase records the reviewed intent with every change, redoes it on the newest main as the normal path, and shows a live board and an Intents view, phone-first on Cloudflare.

          Now hundreds. Two hundred cheap-model agents took almost fourteen hundred small coding tasks on one codebase, and every change went through the real merge queue. Then we aimed more and more of the tasks at the same functions, up to sixty percent. A model redid up to four hundred and sixty-eight collided changes, and they were wrong about as often as fresh work. Losses stayed in the same range: ninety-six, seventy-four, then sixty lost checks, almost all the models' own mistakes, not the landing. What the overlap cost was time: the queue went from forty minutes to over three hours. Splitting it into lanes per module cut the worst case to fifty-three minutes, and fetching ahead in each lane to forty-four and a half, with more requirements passing on main and nothing lost in landing.

            Built to run from your phone

            Say what you want built. Follow every agent, read any change in plain words, and answer only when something needs you.

            You type or say what you want built. You follow every agent in plain words, and you are only asked when something really needs you: a password, money, or a change that keeps failing.

            The timeline shows where time went

            Each agent's time: working, in review, waiting, merging. In the 40-agent build it showed agents waiting for review as long as they worked, so reviewers now scale with the team.

            Every run has a timeline. In the forty-agent build, it showed agents waiting for a reviewer about as long as they worked. So we changed the product: reviewers now scale with the team.

            With 1,000 agents, you browse intents, not agents

            Each request splits into areas, each area into what one agent set out to do, then its change. Status rolls up on every line, stuck things first, and any change leads back to the request it came from.

            A fleet run on 4,063 VS Code files: 4,042 done, 21 did not land, shown first; the same view for a 40-agent app build
            With a thousand agents, nobody can follow agents one by one. So qodebase shows intents: each request, split into areas, then what each agent set out to do, then its change. Every line rolls up its status, stuck things come first, and from any change you can ask why it exists, all the way up to the request.

            Asks: every request, and what became of it

            Each request, the changes it became and their state. Agents log what they decided for you, and ask you only for real decisions.

            Asks lists every request and what became of it: the changes it turned into and where each one is. Agents also log the decisions they made for you, and ask you only for the real ones.
