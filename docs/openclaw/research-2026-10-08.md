# OpenClaw research (Opus research agent, 2026-10-08; numbers via gh, read-only)

- Repo openclaw/openclaw (MIT, TypeScript; formerly Clawdbot/Moltbot; OpenClaw Foundation). "2.0" = v2026.8.1 (2026-08-31).
- 391,628 stars; issues 6,128 open / 52,061 closed (16,282 not planned); PRs 3,344 open / 51,041 merged / 51,924 closed unmerged.
- Last 30 days: ~632 new PRs/day, ~514 merged/day, ~213 new issues/day. steipete-authored PRs ~59% of merges (agent-written).
- CI: ~90 ci.yml runs/hour; success median 7.7 min, p90 12 min; PR runs 30/152 failed in sample; main 47/50 green. ~100 workflow files. 54.6k files, ~19k test files, 8.1 GB on GitHub.
- Pain: AI "software factories" ("prompt requests"); hard cap 20 open PRs/author (label r: too-many-prs applied 2,204 times); no refactor-only / red-main-chasing / feature PRs (plugins instead); GitHub API rate limits (built octopool, pooled cached read relay); 722 security advisories; ~3,049 open issues need a product decision; only 7 open flagged reproducing on main.
- How they work: Peter runs 3-8 Codex agents in parallel, mostly same folder, commits to main, "most code I don't read". ClawSweeper (github.com/openclaw/clawsweeper): 50 Codex in parallel 24/7, ~4,000 issues closed in a day (2026-04-25); budget now 128 workers / 32 scheduled reviews; one edited-in-place comment per item; closes only unchanged, high-confidence, policy-allowed items; @clawsweeper fix/autofix/automerge loops; P0-P3 + impact + merge-risk labels; requires real behavior proof (mock-only flagged); "readiness is not merge authority". Barnacle: deterministic triage/auto-close. gitcrawl (SQLite mirror + embedding clustering), crabbox (leased boxes for tests), clawpatch.
- Dedupe: related reports = one work unit; an existing linked PR is a hard blocker for a new one; stable cluster_id work key; jobs serialized per key.
- Merge gates: NO merge queue; linear history + CODEOWNERS + openclaw/ci-gate, strict off; landing guide: "Do not rebase merely because main advanced"; refresh only on conflict / failing guard / stale-base risk.
- As a corpus: poor default, good stress tier: pin tasks to the fix PR's parent commit; heavy setup (Node 24.16+, pnpm, 19k tests -> per-extension lanes); many bugs need live channels/keys; ground-truth fixes mostly agent-written. Proposed: 50-100 closed issues with one linked merged PR (<200 lines, single area, adds a fail->pass test); replay with K=1/4/16 on a shared moving base; measure fail->pass, pass->pass, time, tokens, conflicts, duplicate work, blinded judge vs real fix.
- Lessons for qodebase: triage + dedupe before work (cluster = work unit, linked PR = lock); per-agent caps; evidence beyond tests; separate readiness and merge authority; API quota + CI capacity as budgets. Challenges: 500 merges/day without a merge queue (our trains must beat that on cost); the leverage was CLOSING work.
