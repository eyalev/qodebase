# F0: Workers AI for documentation comments on VS Code (qb4, 2026-10-13)

Spend so far: $0.11, out of an F0 cap of $2. All calls went through AI Gateway `qodebase-fleet`, in the forq account.
No Claude was used.

## Models, prices and limits (Cloudflare docs, checked 2026-10-13)

Workers AI bills $0.011 per 1,000 neurons, and every response reports its neurons in `usage.neurons`.

| model | $ per M input / output | context | why it is a candidate |
|---|---|---|---|
| @cf/zai-org/glm-4.7-flash | 0.061 / 0.40 | 131k | cheapest capable model; already used by Talk |
| @cf/google/gemma-4-26b-a4b-it | 0.10 / 0.30 | 256k | MoE model with 4B active parameters; fast; supports Batch |
| @cf/zai-org/glm-5.3-flash | 0.15 / 0.50 (cached input 0.03) | 1M | newer GLM; reasoning effort can be set low/high/max |
| @cf/qwen/qwen3-30b-a3b-fp8 | 0.051 / 0.335 | 32k | not run: 32k context is tight for big files |
| @cf/openai/gpt-oss-120b | 0.35 / 0.75 | (not checked) | used as the judge only |

Rate limits (workers-ai/platform/limits):
- **Text generation: 300 requests per minute, per account and per model.** This applies to every model above.
- Models that need Workers Paid (kimi-k2.6/k2.7-code, glm-5.2, the deepseek-v4 models) get 20 per minute, or 50 per
  minute with prepaid AI Gateway credits.
- AI Gateway's own limit is the one set on the gateway; qodebase-fleet is now at 120 per minute.
- At high rates Cloudflare can also answer 429 or 3040 (out of capacity). That has not been measured yet: F2's job.

Thinking costs output tokens, so it is switched off: glm-4.7-flash and gemma-4 take
`chat_template_kwargs: {enable_thinking: false}`, and glm-5.3-flash takes `reasoning_effort: "low"`.

## Method

How the benchmark ran:
- **Files:** 20 non-test `.ts` files from VS Code `src/vs` (commit 7ffca95), each 2-24 KB, spread over base,
  platform, editor and workbench. The pick is seeded.
- **Prompt:** the file with line numbers. The model answers with JSON `{comments:[{line, comment}]}`, one JSDoc per
  undocumented exported or public declaration, at most 25. The model never returns code: we insert the comments
  ourselves, so the output stays small.
- **Verify** (`verify.mjs`): compare the parser's token stream before and after, with JSDoc nodes skipped, and allow
  no new parse errors.
  - A plain `ts.createScanner` loses its place after `${...}` in a template literal. That flagged 4 correct files as
    changed: a false alarm, now fixed.
  - A comment inserted inside a template string is still caught.
- **Judge:** gpt-oss-120b (reasoning low) scored every comment for three things: accurate (nothing wrong),
  helpful (1-5) and placed (sits above the right declaration).
- I also read samples myself.

Run it with `node sim/fleet/bench.mjs --files 20`, then `node sim/fleet/summarize.mjs`. The results are in
`f0-results.jsonl` and `f0-summary.json`.

My read of the comments:
- **glm-4.7-flash** comments the most, but it also comments private methods (against the prompt) and lists every
  @param, even when the name already says it. It has a long latency tail.
- **gemma-4** writes short, correct one-liners, with the fewest that say nothing new.
- **glm-5.3-flash** is the most informative: "used to decide undo stack grouping", "applying smart line-join trimming
  when enabled". It writes the fewest noise @params.

Judging cost 2-3x the work: $0.022-0.031 per model per 20 files. Judge a sample only.

| time at the gateway's current 120 per minute | ~10 min | ~41 min |

Workers AI cost is not the constraint: all of src/vs is under $5 against a $50/day budget. The 20 files tested were
2-24 KB; the bigger files (10% of files are over 28 KB, the largest 249 KB) were not tested, and the chunked calls
for them are an assumption.

Artifacts adds its own cost, which the table leaves out: about four operations per file (fork, fetch, push, landing
fetch). That is ~16k operations for src/vs, i.e. ~$1 past the free 10k a month (billing starts 2026-10-14).

## Prediction for F2 and F3

The fleet's speed is set by request limits, not by the number of agents.
- One model at 300 calls per minute is ~250 files per minute.
- To keep it busy you need about rate x latency in flight: ~30 agents for gemma (6 s), ~70 for glm-5.3 (14 s).

| agents | what happens | throughput |
|---|---|---|
| 10 | latency-bound: 10 / 6 s = 100 calls per minute (gemma) | ~85 files per minute |
| 100 | past the 300 per minute model limit. With the gateway at 120 per minute it caps at 120 | 100 files per minute (gateway 120), ~250 (gateway 300+) |
| 1,000 | the same 300 per minute per model; ~95% of agents wait their turn. Spreading over three models gives 900 per minute | ~250 per model, up to ~750 with three |
| 5,000 | more agents than src/vs has files (4,120): one per file, nearly all waiting. Expect 429s or 3040s unless calls are queued | the same caps |

**The main door** (one main ref) is the next limit after the model. A warm train lands in ~3 s, so ~20 trains a
minute. At trainMax 8 that is ~160 files a minute, which is below one model's 250. Doc-only changes touch separate
files and cannot conflict, so trains can be big:
- one model needs ~15 files per train;
- three models need ~45 files per train.

Lanes by folder add parallel checks, but every lane still pushes to the same main ref. Each lane's train must batch
many files, or a single push must carry several lanes' trains.

So F2/F3 should see three things in this order:
1. the gateway's 120 per minute (raise it to 300 per model);
2. then the main door at trainMax 8 (raise to 32-64 for doc-only changes);
3. then the model's 300 per minute.

Past that, more agents only add waiting. Better than raising the agent count: a queue that hands files to a pool of
~30-70 workers per model, and two or three models side by side.

## Recommendation

- **Model:** gemma-4-26b for the bulk (fastest, cheapest, accurate, fewest noise comments), or glm-5.3-flash where
  richer comments are worth +40% cost and 2x latency. Not glm-4.7-flash: it is wordy and has a long latency tail.
- **Output:** insertions as JSON, never the whole file. Verify with the parser's tokens.
- **Judging:** gpt-oss-120b on a ~5% sample.
- **Gateway:** raise to ~300 per minute per model in use.
- **Landing:** doc-only trains of 32-64 files.

## Gemini on Google AI Studio (2026-10-13, the overflow provider)

These calls go through the same gateway (provider `google-ai-studio`) on the fleet's dedicated key. The call uses
JSON output and thinking set to minimal. Prices are per 1M tokens, from ai.google.dev/gemini-api/docs/pricing
(updated 2026-10-09):
- gemini-3.5-flash-lite: $0.30 / $2.50.
- gemini-3.1-flash-lite: $0.25 / $1.50.
- gemini-2.5-flash-lite: $0.10 / $0.40, but it is "no longer available to new users" (404).
- Gemma 4 on AI Studio: free tier only; paid is "not available".

Rate limits are per project and per tier. The manager saw 360 requests per minute per model on paid tier 2.

|---|---|---|---|
| answered, valid JSON | 20/20 | 20/20 | 6/20 answered, 1 JSON (14 got 429 quota: free tier) |
| code unchanged (verify) | 19/19 | 20/20 | n/a |

| judge: accurate / placed / helpful | 98% / 100% / 3.56 | 99% / 100% / 3.69 | n/a |
| latency p50 / p90 | **1.4 / 2.4 s** | 1.8 / 2.5 s | 7.7 / 21 s |
| $ for 20 files | $0.037 | $0.032 | $0 |
| per 1k files / all src/vs | $2.36 / $9.7 | $2.03 / $8.4 | n/a |

What this means:
- **gemini-3.1-flash-lite is the overflow pick.** Its quality matches the best Workers AI model (glm-5.3-flash), and
  it is 5-8x faster (p50 under 2 s).
- It costs ~3x Workers AI per file, but all of src/vs is still under $10.
- Fast answers mean few agents keep it busy: ~360 requests per minute x 2 s is ~12 calls in flight.
- 3.5-flash-lite writes fewer comments (it skips more) at a higher price.
- Gemma on AI Studio is not usable for the fleet: free-tier quota only, and its answers were not JSON.

Spend for this addition: $0.10 (cap $0.30). F0 total: $0.21.
